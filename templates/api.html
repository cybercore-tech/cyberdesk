🔌 cyberdesk api

Every HTTP endpoint the app serves. The vault root is $CYBERDESK_ROOT; a <path> is a vault-relative .md file. JSON endpoints take/emit application/json; action endpoints take form bodies and 303-redirect.

pages · GET → HTML

GET/portal — counts, tags, recent
GET/allevery note
GET/foldersfolder tree
GET/templatestemplate skeletons
GET/lintvault lint report · ?kind=<kind> filters
GET/repogit activity (app + vault)
GET/apithis page
GET/search?q=<query>full-text search
GET/tag/<tag>notes with a tag
GET/n/<path>render a note (+ TOC, backlinks)
GET/e/<path>edit a note (CodeMirror)

json api

GET/api/titles → [{rel, title}] for every note
GET/api/raw/<path> → {rel, content, exists}
POST/api/save {rel, content, tidy?:bool} → {ok, rel, created, content}. Writes, creates parent dirs, commits. tidy mechanically lints first.
POST/api/tidy {rel?, content} → {content, changed}. No filesystem write.
POST/api/delete {rel} → {ok, rel}. Removes + commits.
POST/api/move {from, to} → {ok, from, to}. to's last segment is slugified.
curl -s localhost:8765/api/raw/Inbox/note.md
curl -s -XPOST localhost:8765/api/save -H 'content-type: application/json' \
  -d '{"rel":"Inbox/note.md","content":"# hi\n","tidy":true}'

actions · form POST → 303

POST/new create from template. fields: template, folder, new_folder, title, filename, tags, needs_review, tidy, date_prefix, open_in, fields_json, body
POST/e/<path>content — save a note
POST/rm/<path>delete a note
POST/lint/fixrel (a path, or * for all fixable)
POST/templates/newname, content? — create a template
